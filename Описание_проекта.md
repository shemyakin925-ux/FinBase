# Описание проекта: локальная исследовательская система для поиска инвестиционных идей

Состояние на 07.11.2026. Источники: `ПЛАН_дообучения.md` (v3.0), `РУКОВОДСТВО_рынок_по_шагам.md`, `docs/`, `_queue_status.md`.

---

## 1. Суть в двух абзацах

Мы строим **локальную исследовательскую систему**, которая ищет инвестиционные идеи в отчётности публичных компаний. Охват: 9 рынков (США, Гонконг, Канада, Австралия, Бразилия, Сингапур, Корея, Новая Зеландия, Россия, плюс Вьетнам) за 2001–2026 годы, **включая компании, ушедшие с биржи**. Система сводит в одну базу отчёты, цены, короткие позиции, распределение акций, макро и цены сырья. Затем она статистически ищет закономерности: какие показатели и их сочетания исторически предшествовали росту, отставанию, поглощению или краху компании. Отвечает на вопросы аналитика LLM-агент, который работает с базой через инструменты.

Главное отличие от «модели, которая выучила отчёты»: **цифры живут в базе, а не в весах модели**. Каждое число в ответе берётся из SQL-запроса или из цитаты документа со ссылкой на страницу. Каждая закономерность проходит путь «гипотеза → проверка на отложенных данных → каталог». Модель дообучаем немного и только навыкам: писать запросы, пользоваться инструментами, извлекать KPI, формулировать проверяемые гипотезы. Всё работает на Mac, без платных подписок.

## 2. Что хотим получить (конечный продукт)

### 2.1 Пять модулей системы

Каждый модуль полезен сам по себе, даже если следующие не дадут результата.

| Модуль | Что делает | Чем | Как поймём, что работает |
|---|---|---|---|
| **A. Данные и извлечение** | факты из отчётов в единых единицах и со ссылкой на источник: финансы, отраслевые KPI, капитал, красные флаги | скрипты; бесплатные модели (Haiku/GLM/Nemotron) для KPI; позже локальный Qwen | точность и полнота на золотых наборах, сверки между отчётами |
| **B. База и поиск** | всё в одном месте по правилу «что было известно на дату»; поиск по тексту отчётов по словам и по смыслу | DuckDB + Parquet, BM25 + эмбеддинги + переранжирование | проверки целостности, тест-ловушка на утечку, полнота поиска |
| **C. Количественные сигналы** | признаки, ранги внутри подотрасли, вероятности исходов | LightGBM, статистика | IC вне выборки, доходность после издержек, устойчивость по годам |
| **D. Поиск связей** | гипотезы → проверка → каталог проверенных связей, в том числе между отраслями и рынками | движок гипотез; LLM как генератор идей | связи, прошедшие проверку на отложенном периоде и после издержек |
| **E. LLM-агент** | вопрос → вызовы инструментов → ответ со ссылками; предлагает гипотезы; пишет записки по идеям | Qwen (база или база + LoRA навыков) | замороженный набор вопросов: точность, **ноль чисел без источника** |

**Порядок доказательства:** A (данные верны) → B (база отвечает правильно и без утечки) → C (данные дают сигнал сверх простых факторов) → D (связи проходят проверку) → E (агент правильно пользуется A–D).

### 2.2 Каким будет результат в работе

1. **Экран идей.** После каждого нового отчёта система пересчитывает признаки и показывает бумаги, которые проходят проверенные правила (например «дёшево и качественно», «дивиденд покрыт деньгами», «устойчивый рост объёмов у добытчика, купленный после падения сырья»). Здесь же отсекаются бумаги с признаками беды: размывание, бумажная прибыль, долговая перегрузка, красные флаги.
2. **Карточка идеи.** По каждой бумаге: показатели на дату, ранги к пирам подотрасли, отраслевые KPI и их динамика, сработавшие связи из каталога, цитаты из отчётов со ссылкой на страницу, риски.
3. **Агент-аналитик.** Отвечает на вопросы вроде «какие девелоперы HK наращивают контрактные продажи при падающем долге?» или «что исторически опережало выручку производителей лифтов?». Ответ собирается из SQL, поиска по тексту и бэктеста. Агент умеет записать новую гипотезу в журнал до её проверки.
4. **Каталог связей.** Проверенные закономерности со статусом (кандидат → проверена → проверена экономикой → работает «вперёд»), числом попыток, эффектом с доверительным интервалом и механизмом.
5. **Журнал решений и работа «вперёд».** Бумажные портфели по замороженным правилам на новых отчётах. Это единственная проверка, которую нельзя подогнать.
6. **Обновление данных.** Цикл «новые отчёты → текст → факты → база → идеи» без ручных правок.

### 2.3 Что считаем главным сигналом (решение пользователя 11.10)

- **Отраслевые метрики реального бизнеса**: м² и контрактные продажи девелоперов, GGR и hold казино, объёмы и себестоимость добычи, сопоставимые продажи ритейла, загрузка, абоненты и т. п. Важны ранг к пирам подотрасли, ускорение и агрегаты подотрасли как опережающие ряды для других отраслей.
- **Уникальные метрики самой компании**, которые выделяет руководство, в сравнении с собственной историей и гайденсом.
- Текстовые флаги и тон — дополнение.
- **Технический анализ исключён** (решение 26.10): моментум, волатильность, ликвидность, бета и расстояние до максимума в гипотезы не идут. В LightGBM ценовые признаки остаются только как контроль.

### 2.4 Две целевые доходности (что предсказываем)

| | Биржевая доходность (TSR) | Рост стоимости на акцию (NAV TR и аналоги) |
|---|---|---|
| Смысл | что получил акционер | сколько стоимости создал сам бизнес |
| Формула | цена с реинвестированием дивидендов и поправками на сплиты | (метрика на акцию в конце + дивиденды) / метрика в начале − 1 |
| Метрика стоимости | — | своя для типа бизнеса: TBVPS для банков, EV для страховщиков, RNAV для девелоперов, NAV запасов для добычи, NAV флота, RAB, сумма частей, нормализованный FCF |

Обе доходности считаются как избыточные (к своей подотрасли). Их разница показывает переоценку рынком. Отдельно предсказываются **исходы**: поглощение с премией, бедствие (ликвидация, делистинг, going concern, долгая приостановка) и прочий выход.

## 3. Почему выбран такой подход

До 18.10 планировалось большое дообучение модели (0,5–3 млрд токенов, месяцы на 27B). 18.10 подход сменили:

| | Большое дообучение на отчётах | База + статистика + агент (текущий подход) |
|---|---|---|
| Точность цифр | модель путает и выдумывает, источник не показать | цифра из таблицы со ссылкой на документ и страницу |
| Новые отчёты | нужно переобучать | достаточно загрузить в базу |
| Закономерности | неявные, проверить нельзя | явные: гипотеза → SQL/бэктест → статистика |
| Заглядывание в будущее | трудно контролировать | фильтр даты в каждом запросе |
| Вычисления | месяцы на M5 Max | дни; LoRA навыков на 10–50 млн токенов |

Прежняя версия плана сохранена целиком в `ПЛАН_архив_v2.0_2026-10-18.md`.

## 5. Как устроена система

```
PDF/HTML отчётов → текст (+OCR) → разделы ─┬─→ факты (финансы, KPI, капитал, флаги) ─┐
                                          └─→ фрагменты текста → поисковый индекс    │
цены, короткие позиции, CCASS, макро, реестры, выходы с биржи ───────────────────────┤
                                                                                     ▼
                              БАЗА ДАННЫХ (DuckDB + Parquet, правило «на дату»)
                                │                    │                    │
                       таблица признаков      поиск по тексту       каталог связей
                                │                    │                    ▲
                      LightGBM, движок гипотез ──────┼────────────────────┘
                                │                    │
                                ▼                    ▼
                    LLM-агент (Qwen + LoRA навыков): вопросы, гипотезы, объяснения
                                │
                                ▼
```

## 6. Принципы и правила

1. **Цифры только из базы.** Модель не хранит факты в весах.
2. **Модель учим навыкам, а не фактам**: SQL, инструменты, извлечение KPI, гипотезы, структура записки.
3. **Никакого заглядывания в будущее.** У каждой строки есть `available_from`. Признаки, поиск и агент в режиме проверки работают «на дату». Сплиты по времени с эмбарго. Тест-ловушка: фиктивный отчёт с будущей датой не должен быть виден ни одной функции.
4. **Без ошибки выжившего.** Ушедшие компании есть во всех выборках. Цена выхода: выкуп при поглощении, −100% при ликвидации. Если цена выхода не найдена или компания обанкротилась, ставим 0 с отдельным флагом, чтобы правило можно было отменить.
5. **Закономерности проверяются по протоколу.** Сначала поиск на раннем периоде (≤ 2012). Затем формула замораживается и один раз проверяется на 2013–2019. Затем экономика: ликвидные бумаги, издержки, вход на следующий день после публикации. Затем работа «вперёд». Записываются все попытки, к ним применяется поправка на множественные проверки (FDR Бенджамини–Хохберга). Тест 2022–2024 задумывался как нетронутый, но **уже использован** при разработке (см. 7.3), поэтому чистой проверкой остаются только будущие данные.
6. **Всё считаем по рынкам и подотраслям.** Единый классификатор: 11 секторов → 59 подотраслей. Ранги считаются внутри «подотрасль × полугодие».
7. **Качество храним колонкой, а не удалением.** Отчёты, не прошедшие сверки, не идут в признаки и обучение.
8. **Ничего лишнего.** В разделы не берём управление, ESG-шаблоны, биографии и китайские дубли страниц.
9. **Одна схема на все рынки.** HK служит образцом, каждый шаг записывается в `РУКОВОДСТВО_рынок_по_шагам.md`.
10. **Только бесплатные модели** для разметки, даже если это займёт недели. **Тяжёлые задачи (обучение, оценка, эмбеддинги, большие извлечения) запускаем строго по одной.**
11. **Гипотезы сначала показываем пользователю списком**, прогоняем только после его отметок.

### 7.2 Качество данных

- **Финансы**, скрипт без модели, все отрасли: ~87 тыс. отчётов. Золотой набор недвижимости: **точность 100%, полнота 96,5%**. Сверка между отчётами по секторам 91–95%. Банки и страховщики требуют отдельных полей и пока покрыты слабо.
- **Отраслевая классификация**: GLM + второе мнение Nemotron для спорных случаев + переспрос у GLM по расхождениям.
- **Цены ушедших HK**: Webb-site плюс точки цен из документов (байбэки, цены выкупа, closing price в отчётах).
- **KPI**: модель извлечения выбрана по сравнению: Haiku 5.5 даёт 88% верных строк против 68% у Nemotron (судья GLM). Каждое число обязано присутствовать в тексте. Проектные и долевые значения отбраковываются, данные сверяются между отчётами.

### 7.3 Статистические сигналы (LightGBM, шаг 9)

Цель: ранг доходности за 12 месяцев к своей подотрасли внутри «подотрасль × полугодие». Обучение ≤ 2018, валидация 2020–21, тест 2022–24, «после» ≥ 2025.

| Модель | IC валидация / тест / после |
|---|---|
| B0 (только рынок) | +0,197 / +0,169 / +0,240 |
| Полная | +0,241 / +0,222 / +0,208 |
| Полная, только ликвидные бумаги | +0,222 / +0,249 / +0,231 |

- Прирост к рынку дают финансы (+0,02 на тесте) и позиционирование: короткие позиции и CCASS (+0,02). Макро помогает на валидации и тесте, но не на «после». KPI и флаги почти ничего не добавляют: сводные KPI не дали устойчивого прироста и на отчётах, где они есть (✎ 06.11), хотя предсказывают будущую выручку (IC 0,16) и рост NAV. На периоде «после» полная модель пока уступает рыночной.
- **Оговорка к уровню IC.** IC 0,2 намного выше обычного для литературы (0,02–0,08), причина не объяснена. Проверки не нашли простого артефакта: IC устойчив к сдвигу входа до 60 дней, к исключению выбывших компаний и к укрупнению групп. Сигнал медленный и в основном отсекает худшие бумаги. Ликвидные, тест / после, без издержек и с перекрытием окон: лучший квинтиль +19,1% / +6,2%, худший −5,7% / −8,4%. Эти числа не являются доходностью стратегии.
- Разброс от сидов и порядка строк сопоставим с мелкими приростами ступеней; порядок строк теперь зафиксирован, используется 5 сидов.
- Бедствие вне выборки (2015–2025): AUC 0,68 по всем секторам. Среди 10% бумаг с наибольшим риском бедствий 1,4% против 0,5% в среднем. Ограничение: в метку пока не попадают дефолты девелоперов 2021–23, которые были приостановлены, но не делистингованы. Метку нужно переопределить.
- Найдена и исправлена ловушка: сравнение с медианой подотрасли давало мнимые +14–21%, потому что доходности скошены. Теперь ориентир — средняя доходность подотрасли.

**«Победители» (+80% за ≤ 4 года)**, по отраслям:
- **Недвижимость** (`docs/WINNERS_HK_RE.md`). У арендодателей работает дисконт к NAV (P/B 0,2–0,5). Долговой фильтр обвала: покрытие процентов < 2, долг/капитал > 1, деньги < 20% краткосрочных обязательств. Такие компании в 45–57% случаев теряли половину стоимости. Сервисные компании лучше избегать. Правила D1–D4, I1–I3, отдельный скрининг для неликвидных бумаг.
- **Сырьё и энергетика** (`docs/WINNERS_HK_ME.md`). Устойчивый рост выручки и объёмов производства работает: при +50% объёмов за 5 лет доля «победителей» 39% против 20%. Покупать лучше после падения цены сырья, а не после ралли. Антиправила: «пик маржи» и рост себестоимости > 10%. Себестоимость единицы раскрывают только ~8% отчётов, поэтому она рассчитывается скриптом (знак совпадает в 76% случаев).
- Скрининги лежат в `EVAL/HK/winners/`.

### Дообучение: что и сколько

- Объём **10–50 млн токенов**, а не миллиарды.
- Чему учим: текст → SQL под нашу схему; цепочки вызовов инструментов (только траектории, проверенные выполнением); извлечение KPI (чтобы локальный Qwen размечал весь корпус без лимитов бесплатных моделей); формулировку гипотез в формате движка; записки (в обучение идут только одобренные пользователем).
- Сначала прогоняем базовую модель на наборе вопросов и обучаем только тем навыкам, где она ошибается. Если «база + примеры в инструкции» работает не хуже LoRA, дообучение для этого навыка не нужно.
- Техника уже проверена: MLX, 4 бита, блочный Gated DeltaNet для гибридной архитектуры Qwen3.5/3.8 (`pipeline/mlx_gdn_chunked.py`, `lora_gdn.py`).
- Ранжирование бумаг силами самой LLM — эксперимент. Проба на 1,7B выучила формат, но связи с исходом не нашла. Успех проекта от этого эксперимента не зависит.

## 10. Итог, к которому идём: критерии успеха

| Что | Критерий |
|---|---|
| Финансы | точность ≥ 97–98% на ключевых полях, полнота ≥ 90% |
| Отраслевые KPI | уровень A ≥ 97% точности |
| База | все проверки зелёные; тест-ловушка на утечку пройден |
| Поиск | recall@10 ≥ 0,8 (цель шага 7а — 90% по метрике судьи) |
| Сигналы | устойчиво положительный IC внутри подотраслей на тесте 2022–2024 и на периоде после 2025; понятно, какие данные дают прирост (лестница B0–B3r); сейчас IC ≈ 0,22, но его уровень не объяснён, а тест уже использован, поэтому решает работа на новых данных |
| Связи | в каталоге есть связи, подтверждённые на отложенном периоде, после издержек и «вперёд»; все попытки записаны |
| Агент | на замороженном наборе вопросов высокая точность, **ноль чисел без источника**, гипотезы в проверяемом формате |
| Дообучение | LoRA заметно лучше и базовой модели, и «база + примеры»; иначе не дообучаем |
| Рабочее место | цикл «новые отчёты → идеи» проходит без ручных правок |

**Финальное состояние:** на каждом из 9 рынков есть своя база «на дату», таблица признаков, поиск по тексту, LightGBM по подотраслям, каталог проверенных связей (включая межотраслевые и межрыночные), агент на локальном Qwen ~27B и экран идей. Система каждый день принимает новые отчёты и выдаёт кандидатов с обоснованием, источниками и рисками. Её правила проверяются на бумажных портфелях «вперёд».
